Inspection report: an invoice app built with AI

Ledgerly is a small invoicing app generated with an AI app builder on Supabase. It worked fine in the preview. Before launch, I reviewed it the way an attacker would and found five problems. Flip the switch to see each one fixed.

Every customer's invoices were public

Critical

What could happen: the invoices table had Row Level Security turned off. The public key that ships in every browser could read all invoices from all customers, with names, amounts and emails.

-- Table created by the AI builder
create table invoices (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users,
  client_name text,
  amount numeric,
  paid boolean default false
);
-- Row Level Security never enabled
alter table invoices enable row level security;

create policy "Users read their own invoices"
  on invoices for select to authenticated
  using (auth.uid() = user_id);

create policy "Users create their own invoices"
  on invoices for insert to authenticated
  with check (auth.uid() = user_id);

Each user now sees only their own rows, enforced by the database, not by the screen.

The master database key was in the browser

Critical

What could happen: the service role key skips every security rule. Anyone who opened the browser's developer tools could copy it and read, change or delete the whole database.

# .env, bundled into the frontend
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
# .env (frontend): only the public key
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...

# Server secret (Edge Function), never shipped to the browser
SUPABASE_SERVICE_ROLE_KEY=********

The leaked key was rotated, and admin work moved to a server function that keeps the key secret.

Any user could make themselves an admin

High

What could happen: the user's role was a column in their own profile, and users were allowed to edit their profile. One request changing role to admin unlocked the admin panel.

create policy "Users update their profile"
  on profiles for update
  using (auth.uid() = id);   -- includes the role column

-- frontend
if (profile.role === 'admin') showAdminPanel();
-- Roles live in their own table with no client write policy
create table user_roles (
  user_id uuid references auth.users on delete cascade,
  role text check (role in ('user', 'admin')),
  primary key (user_id, role)
);
alter table user_roles enable row level security;

create function is_admin() returns boolean
language sql stable security definer set search_path = public as $$
  select exists (select 1 from user_roles
                 where user_id = auth.uid() and role = 'admin')
$$;

Admin access is now checked by the database on every request. Hiding the button is only cosmetic.

Fake "payment received" messages were accepted

High

What could happen: the payment webhook trusted any request that looked like Stripe. Anyone could mark an invoice as paid without paying.

// Edge Function: stripe-webhook
const event = await req.json();
if (event.type === 'checkout.session.completed') {
  await markInvoicePaid(event.data.object.metadata.invoice_id);
}
// Edge Function: stripe-webhook
const body = await req.text();
const signature = req.headers.get('stripe-signature');
const event = await stripe.webhooks.constructEventAsync(
  body, signature, Deno.env.get('STRIPE_WEBHOOK_SECRET')
); // throws if the message didn't come from Stripe

if (event.type === 'checkout.session.completed'
    && event.data.object.payment_status === 'paid') {
  await markInvoicePaid(event.data.object.metadata.invoice_id);
}

Only messages signed by Stripe can change an invoice's status.

The browser decided how much to charge

Medium

What could happen: the checkout took the price from the request sent by the browser. Editing one number paid a $49 plan with $1.

// create-checkout
const { planId, amount } = await req.json();
await stripe.checkout.sessions.create({
  line_items: [{ price_data: { unit_amount: amount, ... }, quantity: 1 }],
});
// create-checkout
const { planId } = await req.json();
const { data: plan } = await supabaseAdmin
  .from('plans').select('stripe_price_id').eq('id', planId).single();
await stripe.checkout.sessions.create({
  line_items: [{ price: plan.stripe_price_id, quantity: 1 }],
});

Prices now come from the server. The browser only says which plan.
